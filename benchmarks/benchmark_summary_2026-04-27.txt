################################################################################
  PART A — Function Generator Mode-Switching Benchmark
################################################################################

1. Purpose
----------
Compare two generations of SCPI command sequences for switching the driving
waveform on a Keysight 33600A (33622A) dual-channel arbitrary waveform
generator connected via USB-TMC (PyVISA).

2. Equipment
------------
  - Function Generator : Keysight 33622A  (firmware A.02.03-3.15-03-64-02)
  - VISA Resource      : USB0::0x0957::0x5707::MY59000656::0::INSTR
  - Interface          : USB-TMC via PyVISA + Keysight IO Libraries
  - Host PC            : Windows (Python 3.14, pyvisa)

3. Method
---------
  Timing instrument : time.perf_counter()  (sub-us resolution on Windows)
  Timing scope      : first inst.write() --> last inst.write() per switch
                      (excludes VISA open/close; includes *OPC? sync between
                       runs to prevent overlap)
  Repetitions       : 50 per scenario
  Statistics        : mean / std / min / max (ms)

  Gen-1 (dual_modal_selector_4modes.py — "run_mode()"):
    Each switch executes the FULL sequence:
      1. OUTP OFF on both channels
      2. Read CSV waveform file from disk (numpy interp alignment)
      3. Upload binary waveform via write_binary_values() to CH1 & CH2
      4. Store waveform to internal memory (MMEM:STOR:DATA)
      5. Configure ARB function, sample rate, voltage, frequency, phase
      6. Set Track ON + phase sync
      7. Set output polarity (NORM/INV per mode)
      8. OUTP ON on both channels

  Gen-2 (dual_modal_4ms.py — "ultra_fast_amplitude_switch()"):
    Startup: preload ALL waveforms once (25k group + 47k group).
    Per-switch logic branches:
      - Same group (e.g. Mode 1 <-> Mode 3): only toggle polarity
        (OUTP OFF -> POL -> OUTP ON, ~3 SCPI commands)
      - Cross group (e.g. Mode 1 -> Mode 2): switch waveform name +
        sample rate + frequency + polarity (~10 SCPI commands)
      - Standby start (None -> Mode X): full parameter setup + OUTP ON

  Mode definitions:
    Mode 1 : 25 kHz group, CH1=NORM, CH2=INV
    Mode 2 : 47 kHz group, CH1=NORM, CH2=INV
    Mode 3 : 25 kHz group, CH1=INV,  CH2=NORM   (same waveform as Mode 1)
    Mode 4 : 47 kHz group, CH1=INV,  CH2=NORM   (same waveform as Mode 2)

4. Results
----------
  Scenario 1a     Gen-1 full switch        mean=163.1 ms  std=23.1 ms  min=121.9 ms  max=263.5 ms
  Scenario 1b-i   Gen-2 same group (1<->3) mean= 10.8 ms  std=19.8 ms  min=  2.0 ms  max=102.3 ms
  Scenario 1b-ii  Gen-2 same group (2<->4) mean=  8.5 ms  std=14.0 ms  min=  2.0 ms  max= 46.8 ms
  Scenario 1b-iii Gen-2 cross (1->2)       mean= 28.9 ms  std=35.5 ms  min=  3.7 ms  max=117.9 ms
  Scenario 1b-iv  Gen-2 cross (2->1)       mean=  5.1 ms  std= 1.4 ms  min=  3.6 ms  max=  9.7 ms
  Scenario 1c     Gen-2 standby start      mean=  6.3 ms  std=11.3 ms  min=  2.0 ms  max= 52.6 ms

  Speed-up Summary:
    Gen-1 average                 : 163.1 ms
    Gen-2 same-group average      :   9.7 ms
    Gen-2 cross-group average     :  17.0 ms
    Gen-2 all-scenario average    :  11.9 ms
    Gen-1 vs Gen-2 overall        :  13.7x faster
    Gen-1 vs Gen-2 same-group     :  16.9x faster
    Gen-1 vs Gen-2 cross-group    :   9.6x faster

5. Observations
---------------
  - Gen-1 bottleneck is CSV file I/O + USB binary upload (~120-260 ms).
  - Gen-2 same-group best case is 2.0 ms (polarity toggle only).
  - Scenarios 1b-i, 1b-ii, 1b-iii show high std (14-35 ms) with occasional
    spikes (max 46-117 ms), likely caused by USB-TMC bus latency jitter or
    Windows scheduling.  Scenario 1b-iv is notably stable (std=1.4 ms).
  - The preload strategy eliminates per-switch disk I/O and waveform upload,
    which accounts for the majority of Gen-1 latency.


################################################################################
  PART B — Process Thread Per-Frame Benchmark
################################################################################

1. Purpose
----------
Measure the image-processing pipeline latency of the Process Thread to verify
it can sustain 120 fps real-time throughput from the Arducam B0332 camera.

2. Equipment & Software
-----------------------
  - Camera          : Arducam B0332 (OV9281, global shutter, mono)
                      640x480 @ 120 fps, MJPG, DirectShow backend
  - Calibration     : TPS rectification map (calibration/tps_rectification_map.npz)
                      Cropped output: 462x314 px
  - OpenCV          : cv2 (compiled with DirectShow support)
  - Host PC         : Same Windows machine as Part A

3. Method
---------
  Timing instrument : time.perf_counter()
  Warmup            : 50 frames (excluded from statistics)
  Measured frames   : 500

  Two modes tested:
    Offline : synthetic random uint8 frames (640x480x3), no camera
    Online  : live camera frames from Arducam B0332

  Pipeline steps timed individually (mirrors camera_threads.process_thread):

    Step 1 — Undistort (TPS remap)
      UndistortCorrector.undistort() calls cv2.remap() with preloaded
      float32 map_x / map_y arrays.  Input ROI is extracted first,
      then remapped with INTER_LINEAR + BORDER_CONSTANT.

    Step 2 — Rotate + Flip
      cv2.rotate(ROTATE_90_CLOCKWISE) then cv2.flip(vertical) and
      cv2.flip(horizontal) per config flags.

    Step 3 — Kalman Predict
      cv2.KalmanFilter.predict() with 4-state (x, y, vx, vy) / 2-meas model.
      Q = 1e-5 * I4,  R = 1e-2 * I2.

    Step 4 — HSV Mask + Morphology + Contour Detection
      find_target_and_angle():
        - cv2.cvtColor(BGR2HSV)
        - cv2.inRange() for yellow + white masks, bitwise_or
        - morphologyEx OPEN (3x3 kernel) + CLOSE (5x5 kernel)
        - findContours(RETR_EXTERNAL) -> max contour by area
        - minAreaRect -> center (cx, cy) + angle

    Step 5 — Kalman Correct
      cv2.KalmanFilter.correct() with measurement jump rejection
      (threshold = MAX_MEAS_JUMP_PX = 80 px).

    Step 6 — EMA + Angle Calculation
      Exponential moving average on position (alpha=0.25) and angle (alpha=0.20).
      Speed calculation via finite difference on mm-scaled coordinates.

    Step 7 — Draw Overlay
      cv2.polylines (bounding box), cv2.circle (centroid),
      cv2.putText x3 (position, angle, speed).

4. Results — Offline Mode (synthetic frames)
--------------------------------------------
  [Per-frame Total Time]
    mean  = 2.30 ms
    std   = 0.76 ms
    min   = 1.27 ms
    max   = 5.16 ms
    p50   = 2.04 ms
    p95   = 3.84 ms
    p99   = 4.55 ms

  [Per-step Breakdown]
    Undistort (TPS remap)            0.87 ms  ( 37.7%)
    Rotate + Flip                    0.27 ms  ( 11.6%)
    Kalman Predict                   0.02 ms  (  1.1%)
    HSV + Morphology + Contour       1.03 ms  ( 44.8%)
    Kalman Correct                   0.00 ms  (  0.1%)
    EMA + Angle Calc                 0.02 ms  (  0.7%)
    Draw Overlay                     0.09 ms  (  4.0%)
    ------------------------------------------------
    Total                            2.30 ms  (100.0%)

  [Throughput]
    Max processing FPS : 435.2 fps
    Headroom           : 6.04 ms  (budget 8.33 ms at 120 fps)

5. Results — Online Mode (live Arducam B0332 frames)
----------------------------------------------------
  [Per-frame Total Time]
    mean  = 2.53 ms
    std   = 0.73 ms
    min   = 1.31 ms
    max   = 4.67 ms
    p50   = 2.52 ms
    p95   = 3.85 ms
    p99   = 4.25 ms

  [Per-step Breakdown]
    Undistort (TPS remap)            0.94 ms  ( 37.2%)
    Rotate + Flip                    0.27 ms  ( 10.5%)
    Kalman Predict                   0.03 ms  (  1.2%)
    HSV + Morphology + Contour       1.14 ms  ( 45.3%)
    Kalman Correct                   0.00 ms  (  0.1%)
    EMA + Angle Calc                 0.02 ms  (  1.0%)
    Draw Overlay                     0.12 ms  (  4.7%)
    ------------------------------------------------
    Total                            2.53 ms  (100.0%)

  [Throughput]
    Max processing FPS : 395.4 fps
    Headroom           : 5.80 ms  (budget 8.33 ms at 120 fps)

6. Observations
---------------
  - Two dominant steps account for ~82% of total time:
      HSV + Morphology + Contour : 45%  (cvtColor + inRange + morphology + findContours)
      Undistort (TPS remap)      : 37%  (cv2.remap with float32 maps on 462x314)
  - Online is ~0.23 ms slower than offline (10%), attributable to real image
    content producing more contours and non-trivial morphology results.
  - std ~0.73 ms is acceptable; no outliers beyond 5.16 ms.
  - The pipeline easily sustains 120 fps with 5.8 ms headroom per frame.
  - Kalman filter and EMA are negligible (<0.05 ms combined).


################################################################################
  PART C — System-Level Timing Budget
################################################################################

  Per-frame budget at 120 fps : 8.33 ms

  Component                     Typical Time    Note
  ----------------------------  -------------- ----------------------------------
  Camera capture (HW)           ~8.33 ms        Handled by dedicated capture thread
  Process Thread pipeline       ~2.53 ms        Measured above (online)
  Main Thread (PID + FG cmd)    variable        Depends on mode-switch frequency

  Gen-2 FG switch (same-group)  ~2-10 ms        Polarity toggle only
  Gen-2 FG switch (cross-group) ~4-29 ms        Waveform + polarity change

  Key finding: the Process Thread uses only 30% of its per-frame budget,
  leaving ample headroom for future additions (e.g., more complex tracking,
  multi-target detection, or higher-resolution processing).

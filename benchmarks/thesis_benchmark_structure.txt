一、測試架構總覽
================

論文中的測試應按照以下邏輯層次組織，每一層都有明確的「要驗證什麼」
和「判定標準是什麼」。不是每項測試都用 8.33 ms 當門檻。

  Layer 1  元件級驗證（各模組獨立測試，確認各自達到設計規格）
  Layer 2  架構級驗證（多執行緒流水線是否如設計般運作）
  Layer 3  系統級驗證（整合後是否達到即時控制需求）

每一層的結果支撐下一層的結論。


二、Layer 1 — 元件級驗證
=========================

每個模組各自有不同的設計規格，不是全部都用 8.33 ms。


【Test 1.1】相機校正品質
─────────────────────────
驗證問題：TPS 畸變校正是否足夠精確？
判定標準：RMS 殘差 < 0.5 pixel（學術常見標準）
測試方法：
  - 偵測網格交點（494 個，亞像素精化）
  - 計算 TPS 擬合殘差
  - 驗證校正後影像的格距一致性與直線度

結果：
  RMS 殘差 = 0.0003 px                      PASS (遠低於 0.5 px)
  校正後格距一致性 CV = 0.62%                PASS
  校正後直線度 RMS = 0.074 px                PASS

論文意義：確認影像量測的幾何精度，後續位置/角度計算可信。

  │ 視覺化：  benchmarks/calibration_viz/*.png                  │

【Test 1.2】影像處理管線速度
─────────────────────────────
驗證問題：Process Thread 能否在 8.33 ms 內處理完一幀？
判定標準：p99 < 8.33 ms（確保 99% 以上的幀都能即時處理）
測試方法：
  - 完整執行 Process Thread 管線（undistort → HSV → morphology
    → contour → Kalman → EMA → overlay）
  - Offline 模式（合成幀）+ Online 模式（實際相機幀）
  - 暖機 50 幀，量測 500 幀

結果：
  Online mean = 2.53 ms, p99 = 4.25 ms, max = 4.67 ms     PASS
  預算使用率 = 30.4%，餘裕 = 69.6%
  最耗時子步驟：HSV+Morphology+Contour (45.3%), Undistort (37.2%)

論文意義：影像處理不是瓶頸，每幀都能在預算內完成。

  ┌─ 對應檔案 ──────────────────────────────────────────────────┐
  │ 測試腳本：benchmarks/process_thread_benchmark.py            │
  │ 結果報告：benchmarks/process_thread_benchmark_results.txt   │
  └─────────────────────────────────────────────────────────────┘


【Test 1.3】函數產生器切換速度（Gen1 vs Gen2）
────────────────────────────────────────────────
驗證問題：第二代預載策略比第一代快多少？
判定標準：不是 < 8.33 ms，而是「比第一代顯著加速」
           （FG 切換是偶發事件，不在每幀預算內）
測試方法：
  - Gen1：每次完整上傳波形（模擬 dual_modal_selector_4modes.py）
  - Gen2：預載波形，切換時只改極性/波形組（模擬 dual_modal_4ms.py）
  - 6 種情境，每種重複 50 次

結果：
  Gen1 (完整上傳)：     mean = 163.1 ms
  Gen2 同組切換 (極性)： mean = 9.7 ms      加速 16.9 倍
  Gen2 跨組切換 (波形)： mean = 17.0 ms     加速 9.6 倍
  Gen2 全情境平均：      mean = 11.9 ms     加速 13.7 倍

論文意義：
  - 第二代設計大幅降低了切換延遲（13.7 倍）
  - 注意：此測試不用 8.33 ms 當判定標準
  - FG 切換屬於「方向改變」事件，在實際運行中極少發生
    （不是每幀都切換，而是馬達需要改變運動方向時才觸發）
  - PID 電壓微調（每 5 幀一次）的耗時在 Test 2.2 中另外量測

  ┌─ 對應檔案 ──────────────────────────────────────────────────┐
  │ 測試腳本：benchmarks/fg_switching_benchmark.py              │
  │ 結果報告：benchmarks/fg_benchmark_results.txt               │
  └─────────────────────────────────────────────────────────────┘


【Test 1.4】FG 電壓微調速度（PID 常規操作）
─────────────────────────────────────────────
驗證問題：PID 控制器每 5 幀發送一次的電壓指令需要多久？
判定標準：mean < 8.33 ms（因為在 Main Thread 上執行，
          會佔用該幀的時間預算）
測試方法：
  - set_voltages() = 2 條 SCPI write
  - 在流水線內量測（pipeline_throughput_benchmark.py 的 Stage 3b）
  - 量測 200 次

結果：
  mean = 1.19 ms, p99 = 2.03 ms                           PASS
  （偶發 max = 48.45 ms 為 USB-TMC 匯流排非確定性延遲，
    見 Layer 2 討論其影響）

論文意義：常規 PID 電壓微調足夠快，不阻塞流水線。

三、Layer 2 — 架構級驗證
=========================

驗證多執行緒流水線架構是否如設計般解耦各級延遲。


【Test 2.1】流水線吞吐量
─────────────────────────
驗證問題：三級流水線是否維持 120 fps 吞吐量？
判定標準：
  - 每一級 p99 < 8.33 ms
  - 掉幀率 = 0%
  - 實際吞吐量 ≥ 120 fps
測試方法：
  - 啟動完整三執行緒系統 + FG（Mode 1 active）
  - FG 電壓指令每 5 幀一次（模擬實際 PID 行為）
  - 暖機 100 幀，量測 1000 幀
  - 分別計時各級

結果：
  Stage 1 Capture Thread ： p99 = 0.07 ms                  PASS
  Stage 2 Process Thread ： p99 = 4.38 ms                  PASS
  Stage 3 Main Thread+FG ： p99 = 2.04 ms                  PASS
  實際吞吐量 = 120.7 fps                                   PASS
  掉幀率 = 0.0%                                            PASS

論文意義：流水線各級都在預算內，系統確實能持續 120 fps。

  │ 測試腳本：benchmarks/pipeline_throughput_benchmark.py       │
  │ 結果報告：benchmarks/pipeline_throughput_results.txt        │
  └─────────────────────────────────────────────────────────────┘


【Test 2.2】模式切換對流水線的影響
───────────────────────────────────
驗證問題：當 Main Thread 執行 FG 模式切換（8-36 ms）時，
          Process Thread 是否受影響？
判定標準：
  - 切換期間 vs 非切換期間的 Process Thread 處理時間無顯著差異
  - 掉幀率仍為 0%
測試方法：
  - 完整三執行緒運行
  - 每 50 幀觸發一次模式切換（交替同組/跨組，共 20 次）
  - 比較切換視窗內外的 Process Thread 統計

結果：
  切換期間  Process mean = 2.80 ms
  非切換期間 Process mean = 2.75 ms
  差異 = 0.05 ms (1.9%)                                    PASS (無顯著差異)
  掉幀率 = 0.0%                                            PASS
  全程 0/1002 幀超過 8.33 ms                                PASS

論文意義：
  這是最關鍵的證據——FG 切換雖然本身超過 8.33 ms，
  但由於在獨立 thread 上執行，完全不影響影像處理的即時性。
  queue 緩衝機制有效吸收了切換期間的延遲。

  │ 測試腳本：benchmarks/mode_switch_impact_benchmark.py        │
  │ 結果報告：benchmarks/mode_switch_impact_results.txt         │

四、Layer 3 — 系統級結論
=========================

綜合前兩層的結果，得出系統級結論。

【結論 1】即時性
  影像處理管線 p99 = 4.38 ms，使用 8.33 ms 預算的 53%。
  系統維持 120 fps 吞吐量，零掉幀。

【結論 2】控制更新率
  PID 電壓微調每 5 幀一次 → 有效控制更新率 = 24 Hz。
  每次電壓微調 mean = 1.19 ms，不阻塞流水線。

【結論 3】切換響應
  Gen2 FG 切換比 Gen1 快 13.7 倍。
  同組切換（方向反轉）mean = 9.7 ms。
  切換不影響影像處理吞吐量。

【結論 4】量測精度
  TPS 校正 RMS 殘差 = 0.0003 px，mm/px = 0.2394。
  位置量測精度遠優於論文需求（< 0.5 px）。
